# 对外网页部署

目标：让互联网上的任何人用 `http://<对外IP>:8080` 使用助手，但**不暴露 Dify 后台**和 API Key。

> 没有使用 IIS，是用 Docker 的 nginx 容器提供网页。

## 架构

    浏览器 ──:8080──> aiwll-web（nginx:1.27-alpine）──> index.html
                        ├─ /api/chat-messages ─> Dify api:5001/v1/chat-messages
                        ├─ /api/parameters    ─> Dify api:5001/v1/parameters
                        └─ 其他路径一律 404

- 文件：`C:\WorkDir\AIWLL\web\`（`index.html`、`nginx.conf.template`、`docker-compose.yml`、`.env`）
- 容器加入 Dify 的 docker 网络 `docker_default`，直接连 `api:5001`
- API Key 由 nginx 在服务器端加上（`.env` 的 `DIFY_APP_KEY`），浏览器看不到
- 网页是单一 HTML 文件，不依赖外部 CDN；开场白和推荐问题从 Dify 读取

## 步骤
1. 在 Dify 为应用创建 App API Key，写入 `web/.env`
2. 在 `web/` 运行 `docker compose up -d`
3. Windows 防火墙（系统管理员 PowerShell）：

       New-NetFirewallRule -DisplayName "AIWLL web 8080" -Direction Inbound -Protocol TCP -LocalPort 8080 -Action Allow

   ✅ 已完成
4. 路由器 port forwarding：外部 TCP 8080 → `192.168.50.204:8080`
   ⏳ 待完成。**不要**转发 80（Dify 后台）
5. 用手机移动网络（关 Wi-Fi）测试 `http://<对外IP>:8080`（可在 https://api.ipify.org 查对外 IP）

## 防滥用
- nginx 限流：全站每分钟 20 则对话（超过回 429）、全站每分钟 60 则上限
- Docker Desktop 会把所有访客的来源 IP 变成网关 IP `172.19.0.1`，所以没办法按 IP 分别限流
- 输入限制 500 字，请求大小上限 16KB，只开放两个 API 路径，GET/POST 以外的方法回 403
- **要在 OpenAI 设置每月预算上限**：https://platform.openai.com/settings/organization/limits

## 测试记录（2026-09-27）
- `GET /` 200，HTML 里找不到 API Key
- `/api/parameters` 回传开场白
- 聊天串流正常；危机关键词触发预设回复
- `/api/conversations`、`/v1/...`、`/console/...`、`/index.html` 都是 404
- 连续 10 次请求，第 4 次开始回 429
- 浏览器实测：推荐问题、串流回答、手机宽度排版都正常

## 已知限制
- 只有 http，没有加密；长期公开建议用 HTTPS（例如 Cloudflare Tunnel）
- 家用网络的对外 IP 可能变动，可用路由器的 DDNS
- 如果路由器 WAN IP 与对外 IP 不同（电信 CGNAT），port forwarding 无效

## 修改后
- 改 `index.html`：刷新页面即生效
- 改 `nginx.conf.template` 或 `.env`：`docker compose restart`
